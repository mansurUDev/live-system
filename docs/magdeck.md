## 1. Суть проекта одним абзацем

Настольный пульт управления медиа (громкость, play/pause, треки), который компьютер видит как обычную Bluetooth-клавиатуру — поэтому он без драйверов работает с MacBook, iPhone, Windows и Android. Начинается как простая коробочка с энкодером и кнопками на ESP32, а в перспективе вырастает в **модульную магнитную систему**: отдельные блоки (кнопки, крутилки, фейдер, экран) слипаются магнитами боками, сами передают друг другу питание и данные через pogo-контакты, и из них собирается любая панель управления — как конструктор. Коммерческий референс, доказывающий спрос: Monogram Creative Console (бывший Palette Gear), модули по $100+.

**Главная цель проекта — не железка, а обучение:** C++, embedded, электроника, пайка, протоколы (BLE, HID, I2C/UART), позже Rust. Железка — приятный побочный эффект.

## 2. Зачем это в «Системе жизни»

- **Обучение через проект.** Новый язык оседает в голове, только когда он — препятствие между мной и штукой, которую очень хочется получить. Курсы и туториалы дают иллюзию прогресса; проект — реальный.
- **Расширение стека.** Сейчас я чистый frontend (React/Next/TS). C++ и embedded — максимальная встряска: ручное управление памятью, компиляция под железо, никакого npm.
- **Мост из моего мира.** Конфигуратор модульной системы — это веб-апп на React + WebHID/Web Bluetooth. Моё нечестное преимущество перед 99% железячников: софт вокруг железки я делаю лучше их.
- **Дальний продуктовый потенциал.** Открытая прошивка + модули дешевле Monogram + видео о процессе разработки = готовая краудфандинг-история. Контент здесь не хобби, а маркетинг.

## 3. Конечное видение (модульная система)

Референс-картинка: набор чёрных брусков — блок с тремя крутилками, блок с экраном, блок с пятью механическими клавишами, блок с фейдером. На торцах — площадки pogo-контактов.

Как это устроено:

- **Магниты + pogo-пины.** Магниты только притягивают и центрируют модули. Ток и данные идут через подпружиненные pogo-контакты (как в MagSafe: через сами магниты ток не гоняют — покрытие, переходное сопротивление, искрение).
- **Мозг в каждом модуле.** В каждом блоке свой копеечный микроконтроллер (ESP32-C3 SuperMini или RP2040-Zero, $2–3), который опрашивает свои кнопки/энкодеры.
- **Общая шина.** Все модули висят на I2C или UART-цепочке. Один модуль — «мастер»: держит BLE/USB-связь с компьютером и опрашивает остальных.
- **Ключевые инженерные задачи** (они же — самое интересное):
  - симметричная распиновка торцов, чтобы модуль цеплялся любой стороной;
  - hot-plug: прицепил модуль на лету — мастер его обнаружил;
  - адресация: как мастер узнаёт, кто подключён и в каком порядке;
  - передача питания по цепочке (бюджет по току, падение напряжения);
  - конфигуратор: назначение действий на кнопки без перепрошивки.
- **Конфигуратор** — веб-приложение на React + Web Bluetooth / WebHID (Chrome). Позже можно упаковать в Tauri (ядро на Rust) — это заодно вход в Rust.

## 4. Техническая база v1 (почему это просто)

- Пульт — это **BLE HID устройство**: для любой ОС он выглядит как Bluetooth-клавиатура с медиакнопками.
- Громкость/play/pause/next/prev — **стандартные HID consumer-коды**, работают из коробки на macOS, iOS, Windows, Android. Требование «чтобы подходило ко всему» решается протоколом, а не кодом.
- Стек v1: **ESP32 + Arduino framework (C++) + библиотека ESP32-BLE-Keyboard** (у неё есть готовые медиаклавиши: KEY_MEDIA_VOLUME_UP и т.д.).
- Схема v1: энкодер EC11 (крутишь — громкость, нажал — play/pause) + 2 кнопки (next/prev). Всё на макетке, без пайки.

## 5. Дорожная карта

### Фаза v1 — «Заработало» (2–4 недели, макетка)
Цель: коробочки ещё нет, но кручу энкодер — на маке меняется громкость.

- [ ] Заказать компоненты для v1 (см. «Покупки», блок v1)
- [ ] Поставить PlatformIO в VS Code (или Arduino IDE для старта), собрать и залить Blink — убедиться, что тулчейн живой
- [ ] Разобраться, что такое GPIO, подтяжка (pull-up/pull-down), дребезг контактов — законспектировать своими словами
- [ ] Кнопка на макетке: нажатие печатает в Serial Monitor
- [ ] Энкодер на макетке: кручение печатает +1/−1 в Serial (понять квадратурный сигнал)
- [ ] Подключить ESP32-BLE-Keyboard, спариться с маком, отправить первую медиакоманду
- [ ] Собрать всё вместе: энкодер = громкость, клик энкодера = play/pause, 2 кнопки = next/prev
- [ ] Проверить на iPhone и Windows (должно работать без изменений)
- [ ] Мини-отчёт в «Систему жизни»: что понял про C++ по сравнению с TypeScript (указатели, память, компиляция)

**Критерий выхода из фазы:** пульт на макетке управляет музыкой на 2+ устройствах, и я могу объяснить каждую строку кода вслух.

### Фаза v2 — «Автономность и корпус»
- [ ] Питание от LiPo/18650 через TP4056, ползунковый выключатель
- [ ] Deep sleep ESP32 + пробуждение по кнопке (замерить ток, посчитать время жизни от батареи)
- [ ] Перенести с макетки на перфоборд, спаять (первый серьёзный опыт пайки)
- [ ] Корпус: 3D-печать (своя или на заказ в Ташкенте)

### Фаза v3 — «Красота»
- [ ] OLED SSD1306 по I2C: громкость, статус, заряд батареи
- [ ] Переезд на ESP32-S3: нативный USB — пульт работает и проводной клавиатурой, и по BLE
- [ ] Механические свитчи (низкопрофильные Kailh Choc дают «плоский» вид как на референсе) + кейкапы

### Фаза v4 — «Тот же проект, другой язык»
- [ ] Переписать прошивку на Rust (esp-rs / esp-hal). Самый дешёвый способ выучить второй язык: задача уже знакома, меняется только инструмент

### Фазы M — «Модульная система» (горизонт 6–12 месяцев, начинать только после v3)
- [ ] M1: два модуля на столе обмениваются данными по UART/I2C, питание второго — через pogo-контакты от первого
- [ ] M2: адресация и hot-plug — мастер обнаруживает модули на лету, определяет порядок
- [ ] M3: конфигуратор на React + WebHID/Web Bluetooth — назначение действий на кнопки из браузера
- [ ] M4: магниты + симметричная распиновка торцов, корпуса, «продуктовый» вид; параллельно — видео о процессе (материал копится с v1: снимать всё с самого начала)
- [ ] M5 (опционально): своя печатная плата в KiCad вместо перфоборда

## 7. Правила обучения (важнее скорости)

1. **ИИ объясняет концепции и ревьюит мой код, но не пишет за меня.** Запрещено просить «напиши прошивку целиком».
2. **Всё, что ИИ показал в примерах, — перепечатываю руками**, не копипастой.
3. **Копировать можно только то, что могу объяснить вслух.** Не могу объяснить строку — разбираю её, пока не смогу.
4. Каждую непонятную концепцию (прерывания, I2C, дебаунс…) — конспектирую своими словами в заметки проекта.
5. Тупик длиннее 2 часов — можно спросить у ИИ направление, но не готовое решение.

*Причина: иначе через месяц будет работающая железка и ноль C++ в голове. Цель проекта — голова, не железка.*

## 8. Очередь «язык + проект» (после v1, по одному за раз)

Не распараллеливаться. Порядок: закончить v1 → взять ОДИН проект отсюда → вернуться к v2.

1. **Swift** — menu-bar утилита для macOS: текущий трек, хоткеи, приём команд от пульта. Софтверная половинка железки.
2. **Go** — телеграм-бот на VPS без serverless: нотификатор новых заказов Upwork по RSS-фильтрам (язык качается, фриланс-воронка кормится) или uptime-монитор ustozim.uz.
3. **Rust** — Tauri-конфигуратор пульта: UI на React, ядро на Rust. Потом esp-rs (фаза v4).
4. **Lua** — Hammerspoon (автоматизация macOS) или PICO-8 (демейк cosmic-wars в 128×128).
5. **GDScript** — геймджем на Godot за 48 часов (Ludum Dare): пощупать движок без обязательств переезда cosmic-wars.
6. **C++ ещё раз, другой класс задач** — Ambilight-подсветка за монитором на WS2812B (тайминги, DMA, захват цвета).
7. **Python** — не встряска, а утилита: автоматизация видео-пайплайна (нарезка, превью, YouTube API); позже — скриптинг KiCad.
8. **C без Arduino** — RP2040 на голых регистрах по даташиту (когда C++ станет комфортным; самый глубокий уровень).
9. **Elixir** — Phoenix LiveView: реалтайм-лидерборд без JS. Переворот картины мира для React-разработчика.
