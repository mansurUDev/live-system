# Трекер — раскладка кнопок активностей

Статус: **утверждено** (2026-08-07, сессия дизайна с макетами на 2560/1512/440).
Документ самодостаточен: следующие этапы реализации читают только его.
Скриншоты утверждённого макета лежат рядом: `tracker-2560.png`, `tracker-1512.png`, `tracker-440.png`.

## Задача и метрика

20–40 кнопок активностей превращались в неструктурированную кучу (auto-fill сетка).
Главная метрика: **секунды от «достал телефон / переключился на окно» до «отметил»**.
Экраны: MacBook Pro 14" (~1512 CSS px), мониторы 27–32" (2560+), iPhone 17 Pro Max (~440 CSS px, одной рукой).
Порядок кнопок стабильный и задаётся пользователем (drag-and-drop — следующий этап). Никаких автоперестановок по частоте.

## Утверждённое решение — коротко

Вариант A «полосы категорий» + горячий ряд из 8 кнопок:

1. Сверху — существующий `RunningBar` («идёт сейчас») + зарезервированный справа слот подсказки следующего шага (цепочки — будущий этап, в UI уже есть место: пунктирный чип «дальше → …»).
2. Ниже — **горячий ряд**: до 8 закреплённых кнопок, крупные плитки. Рекомендованный состав — жизненный цикл дня в хронологии: Зарядка → Готовка → На работу → Работа → Домой → Спорт → Сериал → Сон.
3. Ниже — **полосы категорий**: все остальные кнопки, сгруппированные по `Activity.cat`.

## Источник групп — ЗАФИКСИРОВАНО

- Группы = существующее поле **`Activity.cat`** (`work | health | rest | byt | sleep`, подписи и цвета из `CATS` в `src/constants.ts`). Новая сущность групп НЕ вводится.
- **Порядок полос фиксированный** и одинаковый на всех ширинах: Работа, Здоровье, Отдых, Быт, Сон (порядок `CAT_KEYS`). Полосы не перетаскиваются.
- Порядок кнопок внутри полосы — пользовательский: позиция в массиве `doc.acts` (рендер: стабильная фильтрация массива по cat).
- Пустая полоса (0 видимых кнопок) не рендерится.
- «Порядок жизненного цикла наверху» реализован НЕ порядком полос, а составом и порядком горячего ряда.

## Горячий ряд — данные

- Новое опциональное поле **`Activity.pinned?: boolean`** + константа `HOT_MAX = 8`.
- Горячий ряд = `acts.filter(a => a.pinned)` в порядке массива.
- Закреплённая кнопка отображается **только** в горячем ряду (в своей полосе не дублируется). Счётчик в заголовке полосы считает только видимые в полосе.
- Снятие закрепления возвращает кнопку в её полосу (позиция — по месту в массиве).
- Попытка закрепить девятую — отказ с тостом «В горячем ряду максимум 8 — открепи что-нибудь».
- Закрепление/открепление — в режиме «Настроить кнопки» (переключатель ★ на плитке) и перетаскиванием (см. ниже).
- Нормализация при импорте: `pinned` не boolean → false; закреплённых больше 8 → лишние (по порядку массива) получают false.

## Правила drag-and-drop (для этапа реализации DnD)

- Внутри полосы или внутри горячего ряда → меняется позиция в массиве `acts`.
- Из полосы в другую полосу → `cat` меняется на категорию целевой полосы + тост («“Бег” теперь в “Быт”»).
- Из полосы в горячий ряд → `pinned = true` (+ позиция в массиве); при переполнении — отказ с тостом, кнопка возвращается.
- Из горячего ряда в полосу → `pinned = false` и `cat` меняется на категорию целевой полосы (если отличается) + тост.
- Полосы целиком не перетаскиваются; горячий ряд не сворачивается.

## Раскладка по брейкпоинтам

Все размеры — CSS px. Стиль плиток: фон `linear-gradient(165deg, rgba(22,32,58,.7), rgba(10,16,32,.85))`, рамка `1px solid {color}44`, свечение `inset 0 0 16px {color}0e`; у идущей активности рамка `{color}cc` + внешнее свечение `0 0 18px {color}55` (как в текущем `ActGrid`).

### ≥ 1800 (внешние мониторы, см. tracker-2560.png)

- `RunningBar` — во всю ширину, справа в нём слот цепочки.
- Строка-заголовок «★ Горячий ряд» + справа кнопки «+ Кнопка», «Настроить кнопки».
- Горячий ряд: grid `repeat(8, 1fr)`, плитки min-height 64, имя 16px, низ: точка цвета + подпись категории 10.5px + минуты справа.
- Полосы: grid `repeat(5, 1fr)` — по колонке на категорию; заголовок колонки: квадратик цвета категории + название + счётчик; внутри — чипы 46px в 2 колонки.
- Всё (40 кнопок) видно без скролла.

### 760–1800 (ноутбук, см. tracker-1512.png)

- Горячий ряд: grid `repeat(8, 1fr)`, плитки min-height 56, имя 13.5px, подпись категории скрыта (точка + минуты остаются).
- Полосы горизонтальные: заголовок-строка (квадратик + название + счётчик + линия), под ним чипы 44px c flex-wrap.

### < 760 — телефон (см. tracker-440.png)

- Сверху компактный `RunningBar` (имя, таймер, квадратная кнопка ■) + чип-подсказка цепочки.
- Полосы категорий: **sticky-заголовки** (фон `rgba(7,11,20,.94)`, при скролле текущая категория прилипает к верху), чипы 52px в 2 колонки.
- **Горячий ряд — закреплённый док внизу**: grid 4×2, чипы 50px (точка + имя, минуты скрыты ради места), над доком fade-градиент; док сидит над нижней навигацией с учётом safe area (`env(safe-area-inset-bottom)`), виден всегда.
- Типовая отметка (кнопка цикла дня) = 1 тап большим пальцем без скролла.
- Долгое нажатие 430ms → существующее `BackdateMenu` (5/15/30 мин назад) — работает на любой плитке, включая док.

## Плитка

- Содержимое: точка цвета активности (8px, glow) + название (ellipsis в одну строку) + **минуты за сегодня** справа (JetBrains Mono, 10.5px, `#5b6a86`; формат `ч:мм`; при нуле — пусто; у идущей — «идёт» цветом `#8ff4ff` с миганием).
- Подписи категории на чипах полос больше нет — её даёт заголовок полосы (на плитках горячего ряда ≥1800 подпись категории остаётся, т.к. ряд смешанный).
- «Минуты за сегодня» = сумма отрезков активности за текущие сутки (та же логика, что в DayView).

## Что не меняется

- `RunningBar`, `DayView`, `BackdateMenu`, `ActModal`, `EntryModal` — без изменений (в `RunningBar` добавится слот цепочки, отдельный этап).
- Лимит `MAX_ACTS = 40`.

## Демо-набор макета (32 кнопки)

Горячие 8: Зарядка (health), Готовка (byt), На работу (byt), Работа (work), Домой (byt), Спорт (health), Сериал (rest), Сон (sleep).
Полосы: Работа — Встречи, Код-ревью, Планирование, Почта, Созвон, Деплой, Документация, Обучение; Здоровье — Бег, Прогулка, Бассейн, Врач; Отдых — Игры, Чтение, Музыка, Друзья, Соцсети, Кино; Быт — Уборка, Магазин, Стирка, Ремонт, Документы; Сон — Дремота.
