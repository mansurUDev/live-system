# Система жизни

Командный центр баланса и целей: колесо жизни, трекер времени и аналитика по ним.
Без бэкенда — все данные лежат в localStorage браузера, с экспортом и импортом JSON.

## Что внутри

**Колесо** — до 16 секторов двух видов:
- *сфера* — удовлетворённость от 1 до 10 (процент = оценка × 10);
- *цель* — числовая (накопить 1000 $) или по этапам (чек-лист шагов).

Клик по сектору открывает панель с управлением и историей изменений. Цель, дошедшая
до 100%, празднуется и уезжает в архив достижений, освобождая место на колесе.

**Трекер времени** — сетка кнопок-активностей. Нажатие закрывает предыдущий отрезок и
начинает новый, поэтому день собирается одним касанием на переход. Есть живой таймер,
лента суток, записи задним числом и правка любой записи — с проверкой на пересечения.

**Привычки** — три вида. «Делаю каждый день» — серия с рекордом. «Держусь без» — счётчик
дней без срыва с журналом: каждый срыв записывается с датой и причиной, и на карточке
рядом с рекордом видно «N срывов за месяц» — обнулённый счётчик не притворяется чистым
листом. «Замер» — число без оценки (например, во сколько лёг): для того, что не полностью
в твоей власти, вместо «смог/не смог» копится честная картина со средним за неделю.
У привычки можно задать час риска — брифинг предупредит за пару часов, пока решение ещё
можно принять, а не констатировать срыв постфактум.

**Аналитика** — за день, неделю или месяц: куда ушло время по категориям, столбцы по
дням недели, топ активностей, неотслеженные «дыры», динамика сфер по дневным снимкам,
прогноз даты достижения целей и подсказки-несоответствия (сфера оценена высоко, а
времени на связанную с ней категорию почти не уходит).

**Идеи** — карточки с заметкой, фото и ссылками: что собрать, приготовить, попробовать.
Ссылки при сохранении чистятся от следящих параметров (`igsh`, `si`, `utm_*` и прочих),
через которые по репосту можно вычислить, кто им поделился. Идея про книгу или покупку —
не идея по сути, поэтому у карточки есть «В книги» (переезжает во вкладку «Книги», текст
и ссылки становятся первой заметкой) и «В расходы» (запланированный расход в «Финансах»
с суммой и датой; сама идея не удаляется, только помечается воплощённой).

**Книги** — своя вкладка: позиция, срок «дочитать к» (карточка сама считает, по сколько
страниц в день нужно, чтобы успеть), ссылка на аудиокнигу и заметки по ходу.

**Учёба** — курсы разделами-чек-листом и очередь видео со ссылкой.

**Смотреть** — фильмы, сериалы, дорамы, аниме, мультфильмы и документальные с позицией
«сезон / серия / минута». Раздел **по умолчанию спрятан** из панели и меню: смотреть кино —
дело личное, и через плечо его показывать незачем. Вход — нажатием на точку слева от
заголовка, а на большом экране ещё и на слово «баланса» в подзаголовке; вернуть в общий
список можно в настройках. Книг и учёбы это не касается — они видны всегда.

**Финансы** — планка дохода по месяцам и дневной лимит трат. У каждого расхода своя валюта:
подписка в долларах, аренда в сумах, — а в лимите и итогах они сводятся к валюте отображения
по курсам из настроек. При вводе видно, во что сумма превращается в остальных валютах.

## Облако и вход

Приложение полностью работает без сервера — данные лежат в localStorage под
личным кодом, который спрашивается на входе. Код ничего не охраняет: он нужен,
чтобы на одном устройстве не смешивались записи разных людей.

Если подключить облако, те же данные начинают ездить между устройствами:

1. Создать проект в [Supabase](https://supabase.com) (бесплатного тарифа достаточно
   с большим запасом — это один JSON-документ на пользователя).
2. В **SQL Editor** нового проекта выполнить один раз `sql/schema.sql` из этого
   репозитория — создаёт единственную таблицу `docs`.
3. **Project Settings → Database → Connection string** — взять *pooled*-строку
   (порт `6543`, режим transaction) и добавить её в Vercel как переменную
   окружения `DATABASE_URL`.
4. **Передеплоить**: переменные подхватываются только при сборке.
5. Необязательно: переменная `ACCESS_CODES` вида `mansur:1234,friend:5678`
   ограничит список кодов. Без неё принимается любой непустой код.

Серверная часть — одна функция `api/doc.ts` (GET и PUT), Next.js для этого не
нужен: Vercel запускает функции из папки `api` в любом проекте. Документ хранится
целиком в одной строке таблицы `docs` вместе с номером версии — если на другом
устройстве сохранили свежее, запись отклоняется одним атомарным SQL-запросом
(`INSERT ... ON CONFLICT ... WHERE version = …`), и клиент сначала забирает чужие
правки. Без настроенного хранилища приложение просто продолжает работать локально,
а состояние синхронизации видно по индикатору в шапке.

Ключи в `.env` вписывать не нужно: на Vercel они подставляются сами. Локальный
файл понадобится, только если захочется проверить облако с машины разработчика —
и в репозиторий он не попадает.

### Фото в идеях

Идеи умеют хранить фото — они лежат не в документе, а в Supabase Storage, в
документе остаются только адреса. Нужны ещё две переменные окружения в Vercel
(**Project Settings → API** в Supabase):

- `SUPABASE_URL` — *Project URL* вида `https://<id>.supabase.co`;
- `SUPABASE_SERVICE_ROLE_KEY` — ключ `service_role`. Он секретный: только в
  Vercel, ни в клиент, ни в репозиторий.

Bucket создаётся сам при первой загрузке — руками в Supabase ничего заводить не
нужно. Без этих переменных работает всё, кроме фото: приложение показывает
понятное сообщение и сохраняет идею как есть.

### Телеграм-бот: группы-«избранное» → документ

Бот (`api/telegram.ts`) слушает свои группы и переносит сообщения в приложение:
youtube-ссылка уходит в очередь видео (название подтягивается через oEmbed),
любой другой текст или ссылка становится идеей, а категорией служит название
группы. Дубликаты не создаются, о результате бот отвечает прямо в группе.
Историю, написанную до подключения, бот прочитать не может — это ограничение
самого Telegram: боты видят только новые сообщения.

Подключение:

1. В Telegram у [@BotFather](https://t.me/BotFather): `/newbot` → получить токен.
2. Узнать свой числовой id — например, у [@userinfobot](https://t.me/userinfobot).
3. В Vercel добавить переменные и передеплоить:
   - `TELEGRAM_BOT_TOKEN` — токен из шага 1;
   - `TELEGRAM_SECRET` — любая своя длинная строка;
   - `TELEGRAM_OWNER_ID` — id из шага 2 (бот слушает только владельца);
   - `TELEGRAM_DOC_USER` — user_id строки в docs: имя из `ACCESS_CODES`,
     либо сам код входа, если `ACCESS_CODES` не задан.
4. Включить вебхук (подставить свои значения):

   ```bash
   curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<домен>/api/telegram&secret_token=<СЕКРЕТ>&allowed_updates=%5B%22message%22%5D"
   ```

5. Добавить бота в каждую группу **администратором** — иначе Telegram не
   отдаёт ему чужие сообщения (privacy mode).

Токен и секрет живут только в переменных Vercel — ни в коде, ни в чате их
светить не нужно.

## Разработка

```bash
npm install
npm run dev      # http://localhost:5180
npm run build
npx vitest run   # юнит-тесты чистой логики
```

## Устройство

- `src/logic/` — чистые функции без React: проценты, пересечения интервалов, нарезка
  отрезков, аналитика, прогноз, нормализация импорта, геометрия колеса. Покрыты тестами.
- `src/state/` — один редьюсер над документом плюс контексты данных, времени и тостов.
  Текущее время попадает в систему только через создатели действий, поэтому редьюсер
  детерминирован и проверяем.
- `src/components/` — экраны и модальные окна.
- `src/theme.ts` — токены оформления; `src/global.css` — анимации, ховеры и фон.

Схема данных в localStorage (ключ `sistema-zhizni-v1`) совпадает с форматом экспорта,
так что выгруженный файл можно править руками и загружать обратно.
